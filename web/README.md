# MediaStorm web client

The browser app for MediaStorm. It's a standalone Vite + React 19 + TypeScript project that
talks to the backend only over `/api`. The backend serves the built output at `/watch-next`.
At cutover this moves to `/watch`. Playback hands off to the server-rendered
`/watch/playback.html` player. This app doesn't rebuild the player.

Stack: TanStack Router (file-based) + TanStack Query, Tailwind CSS v4 (tokens as CSS
variables), Radix UI primitives, Vitest + Testing Library, ESLint + Prettier.

## Develop

```sh
npm ci
npm run dev        # http://localhost:5180/watch-next/ — proxies /api and /watch/playback.html to :7777
npm run typecheck
npm run lint
npm run test
npm run build      # -> dist/, served by the backend (handlers.ResolveNewWebAppDir: STRMR_WEB_NEXT_DIR, web/dist, ../web/dist)
```

`WEB_BACKEND=http://host:7777 npm run dev` points the proxy at another server. The base path
lives in `base.config.ts` (`APP_BASE`, or `WEB_BASE` at build time). That one line changes at
cutover.

## Structure

```
src/
  api/         typed fetch client + one module per backend area
  auth/        sessionStore (token, selected profile, PIN unlocks; localStorage) + hooks
  components/  shared UI (index.ts re-exports); shell/ = sidebar, top bar, profile menu
  lib/         playback handoff, theme/accent, cn()
  routes/      file-based routes (routeTree.gen.ts is generated by the Vite plugin; commit it)
  styles/      index.css: design tokens + Tailwind theme mapping
  test/        setup + renderApp() (full app with an in-memory router)
```

## Conventions

API modules: one per area, in `src/api/<area>.ts`.

- Call `apiRequest<T>(endpoint, { method, body, query, signal })`. The endpoint is relative
  to `/api`, for example `'/users/${id}/watchlist'`. The client adds `X-Client-ID`, the
  Bearer token, and `X-Profile-Unlock` for the profiles a request names. It also handles
  refresh and sign-out the same way the native clients do.
- Errors are `ApiError` (`status`, `code`, `body`). Branch on `code`, not on the message.
- Copy request and response types from the Go handlers and models, or from the native
  clients (`native-tvos/StrmrTV/API`, `native-androidtv/core/.../api`). Don't guess them.
  Shared types go in `api/types.ts`. Area-only types stay in the area module.
- Export a query-key factory per area:
  `export const watchlistKeys = { all: ['watchlist'] as const, list: (profileId) => [...all, profileId] }`.
  Put the profile id in every key for profile-scoped data. The cache is cleared on
  logout, and non-`users` queries are dropped on profile switch.
- Pass the Query `signal` through to `apiRequest`.

Routes:

- Signed-in pages live in `src/routes/_app/<name>.tsx` (one file per route). `_app.tsx`
  guards them and renders the shell. Use `<Page title=…>` as the page wrapper.
- Read search params through `validateSearch` (see `_app/search.tsx`). Nested routes use
  folders, for example `_app/details.$mediaType.$id.tsx`.
- Sidebar entries are in `components/shell/nav.ts`.

Components (`@/components`):

- `Button` (variant primary/secondary/ghost/danger, size, loading, leftIcon/rightIcon)
- `IconButton` (icon, label, variant ghost/glass/solid)
- `Spinner`, `Skeleton`, `PageSpinner`
- `EmptyState`, `ErrorState` (error, onRetry)
- `Page` (title, subtitle, actions, bleed)
- `Dialog` (open, onOpenChange, title, description, footer, size)
- `Shelf` (title, action; horizontal scroll with hover arrows)
- `PosterCard` / `LandscapeCard` (title, subtitle, imageUrl, progress 0..1, badge,
  href | onClick; LandscapeCard also takes overlayText)
- `ProfileAvatar`
- `Icon` (inline SVG set in `components/icons.tsx`; add icons there)

Styling:

- Use the token colours only: `bg-bg`, `bg-surface`, `bg-surface-strong`, `glass`,
  `text-fg`, `text-muted`, `text-faint`, `border-line`, `bg-accent`, `accent-soft`,
  `text-danger`, `rounded-card`, `shadow-card`.
- The UI is dark by default. Light mode follows `prefers-color-scheme`.
- `--accent` comes from the profile's `display.appearance.accentColor`.

Playback:

- To play something from any page, use the hook in `src/features/playback/usePlayTitle.tsx`:

  ```tsx
  const { playTitle, overlay } = usePlayTitle();
  <Button onClick={() => playTitle(title)}>Play</Button>              // movie, or series up next
  <Button onClick={() => playTitle(title, { season: 1, episode: 4 })}>Play</Button>
  <Button onClick={() => playTitle(title, { start: null })}>Start over</Button>
  {overlay}                                                            // render once
  ```

  `playTitle` reads the details bundle for the resume point and episode metadata, plays a
  library copy when the profile has one, otherwise resolves through `POST /api/playback/prequeue`
  (polled like the native `PlaybackCoordinator`), then hands off to the player with `returnTo`
  set to the title's details page. `play(PlayRequest)` takes a built request (manual source,
  specific library version). The overlay shows progress with Cancel, and errors.

- Lower level: `openPlayback(params)` from `@/lib/playback` builds the `/watch/playback.html`
  URL and adds `token`, `clientId`, `profileId` and `profileUnlock`; `vodPlaybackParams()` maps
  a resolved stream to the params the player reads (`PlaybackParams` documents them).
- playback.html honours a same-origin, path-only `returnTo` under `/watch-next/…` or `/watch/…`
  (details, live, recordings — see `detailsReturnPath()`); signed-out visits to the player are
  redirected to that path too.

Formatting: Prettier uses 2 spaces, single quotes, semicolons and trailing commas, with
`printWidth` 100. Run `npm run format`.
